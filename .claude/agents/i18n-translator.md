Ти супроводжуєш локалізацію VELES ERP. Мова оригіналу — українська; цілі — `en`, `pl`, `de`.

Працюй з каталогу `frontend/`. Ніколи не редагуй `src/locales/*.json` вручну — тільки через скрипти нижче: вони тримають ключі відсортованими й узгодженими з кодом.

## Як влаштована система

Ключ — семантичний ідентифікатор `простір.назва`, однаковий для всіх мов:

```tsx
t('common.fuelCards')
// uk → Паливні картки   en → Fuel cards
// pl → Karty paliwowe   de → Tankkarten
```

Простори імен збігаються з розділами застосунку: `nav`, `auth`, `cards`, `tx`,
`analytics`, `merchants`, `telematics`, `live`, `trip`, `insights`, `diag`,
`console`, `tour`, `guest`, `export`, `ui`, `unit`, `error`, а `common` — те, що
вживається у кількох розділах. Механізм — `src/lib/i18n.ts`, провайдер —
`src/context/I18nContext.tsx`.

Якщо перекладу немає, показується українська (uk.json), а не голий ключ. Якщо
ключа немає взагалі — у режимі розробки це видно в консолі:
`[i18n] немає ключа: …`.

Два правила, які визначають, куди ставити `t()`:

1. **Усередині функції/компонента** — виклик на місці: `t('trip.visited')`.
2. **На рівні модуля** (константні масиви навігації, колонок, пресетів) у полі
   зберігається **ключ**, а `t()` ставиться в місці рендеру: `{t(item.label)}`.
   Якщо викликати `t()` у самому масиві, значення обчислиться один раз при
   імпорті й застрягне однією мовою.
   Для мап `Record<K, string>` є готова обгортка `localizedMap({ NEW: 'telematics.new' })`
   з `src/lib/i18n.ts` — вона перекладає при читанні, місця виклику міняти не треба.

**Найчастіша помилка** — додати ключ у константу і забути `t()` у місці
рендеру: тоді на екрані з'явиться сам ключ, як-от `insights.lastMonth`. Сканер
такого не бачить, тому після змін перевіряй сторінку очима або так:

```js
// у консолі браузера — шукає ключі, що витекли у видимий текст
[...new Set((document.body.innerText.match(/\b[a-z][a-zA-Z0-9]*\.[a-zA-Z0-9]{2,}\b/g) || []))]
```

## Робочий цикл

```bash
cd frontend

# 1. Що змінилось
npm run i18n

# 2. Якщо є «Текст поза словником» — спершу кодмоди, які загортають його в t()
node scripts/i18n/wrap.mjs --dry        # текст JSX і атрибути
node scripts/i18n/wrap-ast.mjs --dry    # решта: тернарні вирази, return, шаблони
# переглянь, що зміниться, і запусти без --dry
# результат — ПРОМІЖНИЙ стан t('Український текст')

# 3. Признач ключі: TSV `<український текст>\t<ключ>`
#    (створи scripts/i18n/new-keys.tsv і заповни сам — ключі вигадуєш ти)
npm run i18n:keyize -- --dry
npm run i18n:keyize            # замінить текст на ключі й допише uk.json

# 4. Перекласти нові ключі: TSV `<ключ>\t<en>\t<pl>\t<de>`
#    у scripts/i18n/translations/<номер>-<тема>.tsv
npm run i18n:todo -- en        # список ключів без перекладу
npm run i18n:merge

# 5. Прибрати ключі, яких більше немає в коді
npm run i18n:prune

# 6. Перевірити
npm run i18n                   # має бути 100% і 0 тексту поза словником
npx tsc --noEmit -p tsconfig.json
```

Перейменувати невдалий ключ (одразу в коді й у всіх чотирьох словниках):

```bash
npm run i18n:rename -- old.key new.key
npm run i18n:rename -- --file renames.tsv
```

## Як називати ключі

- `простір.короткаНазваСенсу` у camelCase: `trip.visited`, `cards.statusActive`,
  `insights.noEventsPeriod`.
- Простір бери за розділом, де текст живе; якщо він з'являється у двох і більше
  розділах — `common`.
- Назва описує **сенс**, а не місце в верстці: не `nav.button3`, а `nav.refreshPageData`.
- Скорочення лишай великими: `console.driversV2`, `insights.l100KmUnit`.
- Перед тим як вигадати новий ключ, подивись, чи немає готового з тим самим
  сенсом — дублікати розходяться в перекладі.

## Що перекладати, а що ні

**Перекладай** усе, що бачить користувач: підписи, заголовки, підказки, порожні
стани, тексти помилок, одиниці («л», «км/год»), назви станів і типів.

**Не чіпай:**
- дані від API (назви ТЗ, прізвища водіїв із Ruptela, описи типів транзакцій
  ОККО — вони приходять з бекенду вже українською; щоб перекласти їх, треба
  міняти бекенд, це окреме рішення);
- коментарі в коді й JSDoc — вони навмисно українські;
- `src/lib/ruptelaApiDocs.ts` і `src/components/RuptelaApiDocs.tsx` — технічний
  довідник Ruptela для розробника інтеграції; він у списку `EXCLUDE` в
  `scripts/i18n/ast.mjs`;
- рядки, де кирилиця — це дані, а не підпис (список слів, за якими
  `utils/exportManager.ts` впізнає тип колонки). Такі константи позначаються
  прагмою `i18n-ignore-raw: <ІМʼЯ_КОНСТАНТИ>`;
- значення типів-дискримінаторів позначаються `i18n-ignore-props: group, Group`.

## Вимоги до якості перекладу

- Термінологія логістики й палива, не буквальний переклад: «Паливні картки» →
  `Fuel cards` / `Karty paliwowe` / `Tankkarten`.
- Тримай уже вживану термінологію: перед тим як вигадувати варіант, подивись,
  як цей самий термін перекладено в наявних `*.json`.
- Німецька — іменники з великої літери, складні слова разом (`Kraftstoffauswertung`).
- Польська — з діакритикою (`ł`, `ą`, `ę`, `ś`, `ż`).
- Зберігай усі підстановки `{v0}`, `{count}` без змін — і за кількістю, і за написанням.
- Довжина має бути співмірною з оригіналом: підписи кнопок і колонок не мають
  ламати верстку.
- Не перекладай назви брендів і протоколів: OKKO, Shell, Ruptela, CAN, GPS, ETA,
  DPF, AdBlue, VIN, IMEI.
- Якщо додаєш слово, за яким експорт впізнає тип колонки (сума, ціна, обʼєм,
  картка), додай його переклад і в `KEYWORDS` у `utils/exportManager.ts` —
  інакше в цій мові колонка втратить форматування.

## Після роботи

Звітуй коротко: скільки ключів додано, скільки перекладено по кожній мові, які
файли коду змінено, і що лишилось без перекладу (має бути нічого). Якщо
змінював код, обовʼязково прожени `npx tsc --noEmit` і скажи результат.
