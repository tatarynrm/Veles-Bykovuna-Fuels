# Розширений аналіз: коди операцій OKKO та Shell (пальне + дороги, мости, стоянки, T1, збори…)

> **Статус:** аналітичний документ (розширення до
> [`ANALIZ-uniftablytsi.md`](./ANALIZ-uniftablytsi.md)). Код не пишеться.
> **Мета:** повний, деталізований довідник **усіх** типів операцій обох вендорів — не лише
> заправки, а й платні дороги, тунелі/мости, пороми, паркування, мийки, дорожні послуги,
> толлінг (T1/e-toll), комісії та коригування — щоб коректно спроєктувати уніфіковану
> класифікацію операцій у звітній таблиці.
> **Джерела:** мапери бекенду (`okko.mapper.ts`, `shell.mapper.ts`) + офіційна документація
> вендорів (`common/OKKO-Api-Documentation/`, `common/Shell-Api-Documentation/Shell … Addendum
> - July 2020.pdf`).

---

## 0. Головна концептуальна різниця

| | **OKKO** | **Shell** |
|---|---|---|
| Ринок | Україна (внутрішній) | Пан-європейський (мобільність) |
| Що покриває картка | Пальне + магазинні товари на АЗС | Пальне + **уся дорожня мобільність**: толлінг, мости/тунелі, пороми, паркування, мийки, евакуація, дорожні послуги + збори |
| Дороги/мости/стоянки/T1 | **Немає** окремих кодів (це не притаманно внутрішній мережі АЗС) | **Є** — окрема розгалужена таксономія `ProductGroup` + `ProductCode` |
| Система кодів | Числові `trans_type` (реверс-інжиніринг) + `CHST` статуси карток | Дворівнева: `Type` (SalesItem/FeeItem) → `ProductGroupId` (1..30) + окремі `ProductCode` |
| Класифікація в API | бідна (числовий код без словника в доках) | багата (id + назва групи від вендора) |

**Наслідок для таблиці:** «платні дороги, мости, стоянки, T1 і т.д.» — це **майже виключно
операції Shell**. OKKO дає фактично «пальне + магазин + повернення/сторно». Тому уніфікована
класифікація операцій має бути достатньо широкою, щоб вмістити всю Shell-таксономію, а OKKO
лягає лише в кілька її категорій.

## 1. OKKO — коди операцій

OKKO **не публікує** повного словника кодів у наданій документації (Swagger описує
`trans_type` лише як «trn type, BigDecimal»). Наведені нижче коди — **реально розпізнані** в
бекенді (`parseTransactionType`, `okko.mapper.ts`), тобто перевірені на бойових даних.

### 1.1. Типи транзакцій (`trans_type`)

| Код | Опис (UA) | Повернення? | Наша категорія | Примітка |
|-----|-----------|:---:|-----------------|----------|
| `737` | Заправка до повного бака | ні | `FUEL` | звичайна заправка |
| `774` | Списання пального | ні | `FUEL` | якщо `reversal=true` → «Повне скасування транзакції», `RETURN` |
| `775` | Часткова або повна відміна | **так** | `RETURN` | сторно |
| `783` | Повне повернення талону | **так** | `RETURN` | талонна схема |
| `787` | Часткове повернення талону | **так** | `RETURN` | талонна схема |
| *(інші)* | «Заправка пального» / за `reversal` → «Зворотна транзакція / Повернення» | залежить | `FUEL` / `RETURN` | дефолтна гілка |

> Модифікатор `reversal` (bool) може перетворити «списання» на «сторно» — тому категорія
> операції залежить від **пари** (`trans_type`, `reversal`), а не лише від коду.

### 1.2. Продукти / тип пального (`product_id` / `product_desc`)

OKKO не віддає перелічуваного довідника продуктів у доках. Практично:
- `DPP` → «Дизельне паливо» (дефолт у мапері).
- решта видів пального приходять назвою в `product_desc` (Бензин А-95, ГАЗ/LPG тощо) — їх
  треба мапити в наш `code_pal` за назвою.
- `basket_of_goods = true` → у транзакції був **магазинний кошик** (не пальне: товари/кава
  тощо). Це єдиний OKKO-аналог «не-паливної» операції → наша категорія `SHOP`.

### 1.3. Статуси картки (`card_status`, довідник `CHST`)

Не операції, але потрібні для класифікації доступності картки (з `OKKO_CARD_STATUS`,
`okko.mapper.ts`). Ключові: `CHST0` — Активовано (робочий стан), `CHST5` — Заблоковано,
`CHST6/7` — Загублено/Викрадено, `CHST99` — Перенесено між контрактами. Повний перелік — у
мапері (CHST0…CHST21, CHST99). Обслуговувані: `CHST0`, `CHST4` (+ `ACTV`).

### 1.4. Чого в OKKO немає
Платних доріг, мостів/тунелів, поромів, паркування, мийок, толлінгу (T1/e-toll),
віньєток — **немає окремих кодів**. Якщо колись зʼявляться (напр., партнерські сервіси), вони
прийдуть новими `trans_type`/`product_id` і додаватимуться в мапінг за фактом.

## 2. Shell — коди операцій (повна таксономія)

Shell має **дворівневу** класифікацію (Addendum July-2020, ст. 13–14):
1. **`Type`** (верхній рівень рядка): `SalesItem` (продаж) або `FeeItem` (збір).
2. **`ProductGroupId`** (1..30) + **`ProductGroupName`** — категорія товару/послуги (джерело
   істини — назва від вендора).
3. Окремо існує **`ProductCode`** (макс. 8 символів) — код продукту в платформі Shell, зі
   **своєю** нумерацією для толлінгу (напр., `11 Tunnel/Bridges`, `12 Motorway toll`,
   `13 Ferries`) — **не плутати** з `ProductGroupId`.

### 2.1. Повний довідник `ProductGroupId` (1..30)

Позначки: **Пал** = пальне (`is_fuel`), **Дор** = дорожня мобільність (`is_road`),
**Збір** = комісія (`is_fee`).

### 2.2. Довідник `ProductCode` — толлінговий кластер (окрема нумерація!)

З параметра-фільтра `ProductCode` (Addendum, ст. 4):

| ProductCode | Значення (EN) | UA | Наша категорія |
|-------------|---------------|----|-----------------|
| `10` | TMF Charges | Комісія TMF | `TOLL_FEE` |
| `11` | **Tunnel/Bridges** | **Тунелі / мости** | `BRIDGE_TUNNEL` |
| `12` | **Motorway toll** | **Плата за автомагістраль (толл)** | `TOLL` |
| `13` | **Ferries** | **Поромні переправи** | `FERRY` |

> ⚠️ Пастка: `ProductCode = 11` означає «Tunnel/Bridges», але `ProductGroupId = 11` означає
> «Lubricants». Це **дві різні системи кодування**. У таблиці зберігаємо `product_code_src`
> (сирий ProductCode) **і** `product_group_id`/`product_group_name` окремо, а класифікуємо в
> `oper_cat` за їх сукупністю (див. §3).

### 2.3. Дорожня мобільність — деталізація (те, про що йдеться в задачі)

Усі «платні дороги, мости, стоянки, T1» у Shell розкладаються так:

- **Платні автомагістралі (toll):** `ProductCode 12 Motorway toll`; управління — через групи
  `27 TMF / 28 TMF Charges / 29 TMF VAT exempt`. Тип картки в даних містить маркери
  `TMF ETOLL` (напр., `"CardType": "GB FLT INT TMF ETOLL"`) — ознака під'єднаного e-toll.
- **Мости / тунелі:** `ProductCode 11 Tunnel/Bridges` → `BRIDGE_TUNNEL`.
- **Пороми:** `ProductCode 13 Ferries` → `FERRY`.
- **Паркування:** `ProductGroupId 19 Parking` → `PARKING`.
- **Мийка:** `ProductGroupId 18 Car wash` → `CARWASH`.
- **Евакуація/аварійні:** `ProductGroupId 20 Breakdown Services` → `BREAKDOWN`.
- **Дорожні послуги (загальні/основні):** `ProductGroupId 17 Controlled Road Services`,
  `30 Essential road services` → `ROAD_SERVICE`. Сюди ж, як правило, потрапляють **віньєтки**
  (SHELL_GROUP_NAME_UA у мапері вже має ключ `vignette` → «Віньєтка») — вони приходять назвою
  продукту в межах дорожніх послуг.

#### Про «T1»
`T1` — це **класифікатор дорожньої/толлінгової операції**, а не окремий числовий код у
специфікації Shell. У практиці транспортних карток `T1` зазвичай позначає **толл-клас/категорію
транзакції на платній дорозі** (клас ТЗ або тип толл-документа). У даних Shell така операція
приходить як звичайний толл-запис (`ProductCode 12` / групи `27–29 TMF`) з міткою `T1` у
**тексті** `ProductName`/`ProductCode`. Тому:
- **не вигадуємо** для `T1` окремий числовий код;
- зберігаємо сирий `product_code_src` + `product_name_src` (де і буде «T1») дослівно;
- у класифікації відносимо до `TOLL` (за потреби — з підтипом у `product_code_src`).
- ⚠️ уточнити на **бойових** даних Shell точний рядок, яким приходить `T1` (тест-середовище
  `api-test.shell.com` може його не містити) — це в списку відкритих питань.

### 2.4. Повернення / сторно (Shell)

Не окрема група, а **прапорець**, що визначається трьома способами (`parseShellTransactionType`):
1. `CreditDebitCode = 'C'` (кредитовий бік), або
2. `RefundFlag ∈ {y,yes,true,1}`, або
3. `GrossAmount < 0` (відʼємна сума).
→ `is_return = 1`, категорія лишається (напр., `FUEL`), але операція від'ємна.

### 2.5. FeeItem vs SalesItem
`Type = FeeItem` → сервісний/картковий збір (групи 21–29). Для fee-рядків Shell кладе суму
збору в `InvoiceNetAmount`, а `TransactionDate` = дата збору. Наш прапорець `is_fee` уже це
розпізнає (`okko`-аналога немає).

## 3. Уніфікована класифікація операцій (наш довідник `oper_cat`)

Щоб звіти працювали однаково для всіх вендорів, обидві таксономії зводяться в **один
власний довідник категорій операцій**. Пропозиція набору (розширюваний):

| `oper_cat` | Значення | is_fuel | is_road | is_fee | OKKO джерело | Shell джерело |
|------------|----------|:---:|:---:|:---:|--------------|---------------|
| `FUEL` | Пальне (ДП, бензин, газ) | ✔ | | | `737/774`, види пального | груп. 2–7, 9 |
| `ADBLUE` | AdBlue / альт. пальне | ✔ | | | (за назвою) | груп. 8 |
| `LUBRICANT` | Мастила | | | | (магазин) | груп. 11 |
| `SHOP` | Магазинні товари/їжа/напої | | | | `basket_of_goods` | груп. 10,12–16 |
| `TOLL` | Платні автомагістралі | | ✔ | | — | PC 12; груп. 27 |
| `TOLL_FEE` | Толлінгові комісії (TMF) | | ✔ | ✔ | — | PC 10; груп. 28,29 |
| `BRIDGE_TUNNEL` | Мости / тунелі | | ✔ | | — | PC 11 |
| `FERRY` | Пороми | | ✔ | | — | PC 13 |
| `PARKING` | Паркування | | ✔ | | — | груп. 19 |
| `CARWASH` | Мийка авто | | | | — | груп. 18 |
| `ROAD_SERVICE` | Дорожні послуги / віньєтки | | ✔ | | — | груп. 17,30 |
| `BREAKDOWN` | Евакуація / аварійні | | ✔ | | — | груп. 20 |
| `FEE` | Загальні/карткові/сервісні збори | | | ✔ | — | груп. 21,22,24,25,26 |
| `ADJUSTMENT` | Грошові коригування | | | ✔ | — | груп. 23 |
| `RETURN` | Повернення / сторно | | | | `775/783/787`, `reversal` | прапорець `is_return` |
| `OTHER` | Нерозпізнане | | | | дефолт | груп. 1 / дефолт |

> `RETURN` тут — зручний «плоский» ярлик, але в таблиці краще тримати **окремий прапорець**
> `is_return` поряд із базовою `oper_cat` (щоб «повернення пального» лишалось `FUEL` +
> `is_return=1`, і сума правильно віднімалась). Так само `is_fee`, `is_road`, `is_fuel` —
> похідні прапорці для швидких зрізів.

## 4. Що це додає до структури таблиці

До схеми з [`ANALIZ-uniftablytsi.md`](./ANALIZ-uniftablytsi.md) §5 додати/уточнити:

| Колонка | Тип | Призначення |
|---|---|---|
| `oper_cat` | `VARCHAR2(20)` | наша уніфікована категорія операції (див. §3) |
| `oper_code` | `VARCHAR2(50)` | сирий код вендора (`774` / `SHELL_G12` / ProductCode) |
| `oper_desc` | `VARCHAR2(500)` | людяний опис українською |
| `product_code_src` | `VARCHAR2(50)` | **сирий** ProductCode Shell (тут буде «T1»/`11`/`12`/`13`) |
| `product_group_id` | `NUMBER` | Shell `ProductGroupId` (1..30); NULL для OKKO |
| `product_group_name` | `VARCHAR2(200)` | Shell `ProductGroupName` (джерело істини) |
| `is_fuel` | `NUMBER(1)` | пальне |
| `is_road` | `NUMBER(1)` | дорожня мобільність (толл/міст/пором/паркінг/послуга) |
| `is_fee` | `NUMBER(1)` | збір/комісія |
| `is_return` | `NUMBER(1)` | повернення/сторно |

**Довідникова таблиця-мапінг** (рекомендовано окремо, напр. `AGTDAT.CCFUEL_OPERMAP`):
`(vendor, vendor_code_type, vendor_code) → (oper_cat, is_fuel, is_road, is_fee, opis_ua)`.
Тоді додавання нового коду/вендора — це **рядок у довіднику**, без зміни коду завантажувача.

| Явище з задачі | Вендор | Звідки береться | `oper_cat` |
|----------------|:------:|-----------------|------------|
| Платна дорога (магістраль, toll) | Shell | `ProductCode 12`, групи TMF 27–29 | `TOLL` / `TOLL_FEE` |
| Міст / тунель | Shell | `ProductCode 11` | `BRIDGE_TUNNEL` |
| Пором | Shell | `ProductCode 13` | `FERRY` |
| Стоянка / паркування | Shell | `ProductGroupId 19` | `PARKING` |
| Мийка | Shell | `ProductGroupId 18` | `CARWASH` |
| Евакуація | Shell | `ProductGroupId 20` | `BREAKDOWN` |
| Дорожні послуги / віньєтка | Shell | групи 17/30, назва `vignette` | `ROAD_SERVICE` |

## 6. Відкриті питання

1. **Точний рядок «T1»** у бойових даних Shell (`ProductName`/`ProductCode`) — перевірити на
   проді; від цього залежить правило мапінгу в `TOLL`.
2. **OKKO поза пальним:** чи будуть у нашому контракті OKKO магазинні/талонні операції, чи
   лише заправки? Впливає на потребу в `SHOP` для OKKO.
3. **TMF (27–29):** рахувати як `TOLL` (дорожня мобільність) чи як `FEE` (збір)? Пропозиція —
   `TOLL_FEE` з обома прапорцями (`is_road=1`, `is_fee=1`).
4. **Гранулярність довідника:** тримати мапінг у таблиці (`CCFUEL_OPERMAP`) чи в коді мапера?
   Рекомендація — у таблиці (додавання кодів без релізу).
5. **Нові вендори (Укрнафта/WOG):** їхні толл/дорожні коди (якщо є) додаються рядками в
   `CCFUEL_OPERMAP` — DDL не змінюється.
